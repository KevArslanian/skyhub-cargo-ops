# UI/UX audit: viewport-fitting, redundancy removal, consistency pass

A housekeeping change that tightens the shell's desktop layout model, removes two redundancies (topbar theme toggle, dead `/reports` route), fixes the mobile hamburger media query, and rewrites `PageHeader` so it actually renders the title/eyebrow/subtitle it's been silently swallowing. The approach is CSS-driven: a single `@media (min-width: 1280px)` block turns `shell-content` into a viewport-height boundary and gives every `page-workspace` internal scrolling, replacing per-page hacks (hardcoded `628px`, `calc(100svh - ...)`) with a uniform flex model.

**Watch for:** The `shell-content` topbar uses `sticky top-0` which is neutralized by the new `overflow: hidden` on its parent at xl+ (confirmed — sticky requires a scrolling ancestor, and the parent no longer scrolls). This is functionally harmless because the topbar sits at the top of a flex column anyway, but it leaves dead CSS that could confuse future maintainers. The `alerts-viewport` is defined twice in the same media query block with conflicting intent (likely pre-existing, but the diff touches adjacent lines).

## High-level view

The layout strategy moves from per-page viewport hacks to a single constraint at the shell level: `shell-content` becomes `height: 100svh; overflow: hidden` on xl+, and each `page-workspace` fills remaining space via `flex: 1` with its own scroll container. This eliminates the dashboard's hardcoded `628px` and AWB tracking's `calc()` expression in favor of natural flex sizing. On mobile (< 1280px), `page-workspace` reverts to `height: auto; overflow-y: visible` for natural document flow.

The hamburger trigger switches from a device-capability query (`any-hover: none` + `any-pointer: coarse`) to a simple viewport-width test (`min-width: 1024px` hides, default shows). This matches the existing `lg:` breakpoint already governing the sidebar's translate/visibility.

`PageHeader` was a no-op component — it returned `null` unless `actions` was provided. The rewrite always renders the eyebrow/title/subtitle block and conditionally renders the actions slot. The shipment-ledger page migrates from a bespoke `ledger-control-header-compact` section to the shared `PageHeader`, gaining consistency but losing its `aria-labelledby` link on the `<main>` element (minor accessibility regression, see below).

<summary>Issues (4)</summary>

1. **Dead `sticky` on topbar at xl+** (confirmed) — `shell-topbar` has `sticky top-0` via Tailwind, but its parent `shell-content` now has `overflow: hidden` at xl+, which disables sticky positioning. The topbar stays put anyway (it's `shrink-0` in a flex column), so the sticky declaration is dead weight. Remove `sticky top-0` from the header's class list at xl+ or document why it's kept for sub-xl.

2. **Duplicate `alerts-viewport` rule block** (confirmed) — Within the same `@media (min-width: 1280px)` block, `.alerts-viewport` is defined twice: once with `min-height: 100%; height: auto; gap: ...` and immediately again with `height: auto; max-height: none; overflow: visible`. The second block overrides the first's properties. Consolidate into a single rule set to avoid confusion.

3. **Shipment-ledger lost `aria-labelledby`** (confirmed) — The old `<main aria-labelledby="shipment-ledger-title">` linked to an explicit `<h1 id="shipment-ledger-title">`. The new code relies on `PageHeader` rendering an `<h1>`, but that `<h1>` has no `id` and the `<main>` has no `aria-labelledby`. Screen-reader landmark navigation no longer announces the page title for this route. Add `id` to the `PageHeader` `<h1>` and restore `aria-labelledby` on the `<main>`, or pass an `id` prop through `PageHeader`.

4. **`page-workspace` scrollbar may not reach `pb-6` spacing** (possible) — The `<main>` element wrapping `page-workspace` has `pb-6` (24px bottom padding), but since `page-workspace` itself has `overflow-y: auto` on xl+, the scroll container is the child, not the `<main>`. Content scrolled to the bottom will butt against the `<main>`'s padding boundary. If the padding applies outside the scroll viewport, the last few pixels of page content could be clipped.

## Viewport-fitting via shell-content boundary

```
┌─ shell-content (100svh, overflow:hidden) ─────────┐
│  ┌─ header.shell-topbar (shrink-0, sticky†) ────┐  │
│  └──────────────────────────────────────────────┘  │
│  ┌─ main (flex-1, min-h-0, pb-6) ──────────────┐  │
│  │  ┌─ div (h-full) ─────────────────────────┐  │  │
│  │  │  ┌─ .page-workspace (flex:1, scroll) ┐ │  │  │
│  │  │  │           page content              │ │  │  │
│  │  │  └─────────────────────────────────────┘ │  │  │
│  │  └────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────┘
  † sticky is dead at this breakpoint
```

The `sticky top-0` on `shell-topbar` (line 617 of app-shell.tsx) no longer functions at xl+ because `overflow: hidden` on the ancestor disables the sticky positioning context. It's still useful below xl+ where `shell-content` doesn't have overflow:hidden and the document scrolls naturally, so removing it outright would regress mobile. A conditional approach (remove sticky only at xl+ via a responsive utility) would eliminate the dead declaration without breaking sub-xl behavior.

The `pb-6` on the `<main>` element creates a gap between the main's bottom edge and the viewport boundary. Since `page-workspace` is the actual scroll container at xl+, content that reaches the bottom of page-workspace won't necessarily have 24px of breathing room — the padding lives on the non-scrolling parent. Pages that define their own bottom padding internally are unaffected, but any page relying on the shell's `pb-6` for bottom spacing will appear clipped at the scroll boundary.

## PageHeader accessibility regression

The shipment-ledger migration drops `<main aria-labelledby="shipment-ledger-title">` and its associated `<h1 id="shipment-ledger-title">`. The new `PageHeader` renders an `<h1>` but without an `id`. Screen readers navigating by landmarks will announce the `<main>` without a label for this route. A fix would be to accept an optional `id` prop on `PageHeader`, pass it to the `<h1>`, and restore `aria-labelledby` on the page's `<main>`. This could also be applied to other pages as a progressive enhancement.

## Duplicate alerts-viewport declarations

In the xl+ media query block, `.alerts-viewport` appears twice:

```css
/* First occurrence */
.alerts-viewport {
  min-height: 100%;
  height: auto;
  gap: clamp(1rem, 1.2vw, 1.4rem);
}

/* Second occurrence */
.alerts-viewport {
  height: auto;
  max-height: none;
  overflow: visible;
}
```

The second block was likely authored separately and never merged with the first. The diff splits out `dashboard-viewport` and `flightboard-viewport` from the first rule (they previously shared a selector), which makes the orphaned second `.alerts-viewport` block more visible. Consolidating them into one declaration would reduce cognitive load.
